# AEOS Global Agent Rules

## 1. Mission

All AI agents operating inside AEOS must follow a unified engineering workflow.

The objective is:
- Reliable software delivery
- Maintainable architecture
- Automated workflows
- High-quality documentation


## 2. Before Any Change

Agent MUST:

1. Inspect existing project structure.
2. Read relevant documentation.
3. Understand dependencies.
4. Avoid unnecessary modifications.
5. Preserve existing functionality.


## 3. Architecture Rules

Agent MUST:

- Follow modular architecture.
- Keep separation of concerns.
- Avoid monolithic files.
- Prefer reusable components.
- Maintain clear folder organization.


## 4. Coding Rules

Agent MUST:

- Write clean and readable code.
- Use meaningful names.
- Add error handling.
- Add comments only when needed.
- Follow project coding standards.


## 5. Testing Rules

Before completing any task:

- Run available tests.
- Validate changed components.
- Report errors clearly.


## 6. Documentation Rules

Any major change requires:

- Updated documentation.
- Updated configuration examples.
- Updated changelog when applicable.


## 7. Git Rules

Agents MUST:

- Work on feature or phase branches.
- Never commit directly to main.
- Create meaningful commit messages.
- Keep commits focused.


## 8. Security Rules

Agents MUST NOT:

- Commit API keys.
- Commit passwords.
- Expose secrets.
- Modify security settings without approval.


## 9. Completion Criteria

A task is complete only when:

- Code works.
- Tests pass.
- Documentation is updated.
- Git status is clean.
